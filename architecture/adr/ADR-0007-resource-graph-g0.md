# ADR-0007 Hybrid Sharing の Resource Graph 契約（G0）

## 状態

Proposed。Issue #348 の自律開発試験。基点は main の `2812c90f0def3a8d2c7fa88e14ddca425327d936`。

## 決定案

Go の純粋な型と、JSON Schema Draft 2020-12 の契約を用意する。JSON 形状を Schema で、同一 Workspace 内の整合性を Go で検証する。契約版は文字列 `0.1`。3 種のレコードはそれぞれ `type` を持つ。未知の型・版・フィールドは Schema 検証で拒否する。今後の読み込み経路では重複キーを含む入力を厳格に検証してから Go の型に変換する。

| レコード | 識別子と責務 |
| --- | --- |
| Workspace | `workspace_id`。グラフと同期の境界。v0.1 の関係と親版はこの境界内に収める。 |
| Resource | `resource_id`。ワークスペース内で安定した不透明 ID。パス、タイトル、内容ハッシュの変更に左右されない。 |
| Revision | `revision_id` と `resource_id`。親版は同じ資料に属する。親なし、分岐、複数親を許し、親の循環を拒否する。子を持たない版が Head となり、時刻で片方を選ばない。 |
| Blob | `sha256` はその版の正確なバイト列を表す。長さとメディア型を別に持つ。内容ハッシュは Resource ID と独立。任意の `metadata_sha256` は別メタデータの内容を表し、表現方式はアダプターの課題とする。 |
| Relation | `relation_id`。関係は出発元の版に属する。参照を編集するときは新しい出発元の版を作る。 |
| ShareRequest / GrantRef | 要求は Workspace とルート版を指定する。任意の GrantRef は Ephy v2 の policy_id と scope_id を参照する。既存 Grant は外部転送を許可しない。受け取った JSON から認可は発生しない。 |
| ShareSnapshot | 添付用の公開投影。内部 Graph から発行し、ルートと収録物にはそのスナップショット内だけで使う ID を割り当てる。Blob のハッシュは投影後の配布バイト列から計算する。 |
| ChangeEvent | `operation_id` は Workspace 内で一意。G0 の event は `revision_added` を参照する。実行時の再送では同じ ID と内容を冪等に扱い、異なる内容での再利用を競合として扱う。構造の検証では集合内の重複 ID を拒否する。 |

`legacy_doc_id` は Markdown の既存値を保持する別名。Context が使う境界の空白除去をした値をそのまま渡す。大文字小文字、Unicode、区切り文字は書き換えない。資料ごとに Workspace 内で別名が一意であることを検証する。重複・欠損を診断する棚卸し、ID 発行、パス別名の保存は後続で決める。ケース衝突や NFC/NFD が異なるファイルが同じ資料だと推測しない。

## 版固定と参照

| 関係 | Graph での参照方法 | Snapshot の収録条件 |
| --- | --- | --- |
| `embeds` | 固定版または最新版追従 | 固定した収録版を使う。最新版追従から書き出す場合は一意に解決した版を明示して固定する。 |
| `cites` | 固定版 | 許可済みの根拠資料を、利用者が同梱する場合にだけ辿る。 |
| `derived_from` / `supersedes` | 固定版 | 来歴や訂正を表す。依存として自動追加しない。 |
| `related_to` | 固定版または最新版追従 | 依存として自動追加しない。 |

最新版追従で Head が複数ある場合は利用者またはアダプターに競合を返す。固定参照の欠損や版・資料の取り違えは拒否する。関係の循環は有効。今後の依存閉包は訪問済みの版を追跡して停止する。Snapshot は投影された `embeds`／`cites` からルートを辿れる収録物だけを持つ。

アンカーは固定版が対象。Markdown は UTF-8 の半開バイト範囲、PDF は 1 始まりのページと任意の表示ページ上の矩形（左上原点、幅・高さを 100 万分率で表す整数）、CSV は 1 始まりの包含行列、音声は半開ミリ秒範囲とする。PDF のページ数や CSV の実際の範囲、UTF-8 境界の照合は Blob を読めるアダプターの責務。PDF の矩形と既存ボード座標との変換にはページの回転・クロップを考慮する。

## 既存実装との接点

| 既存機能 | 互換境界 |
| --- | --- |
| Context Protocol v1/v2、ADR-0004 | search/read の `doc_id` と canonical SHA-256 は既存の意味で継続。Karte が actor・capability・project・tag・sensitivity・provenance を判定する。 |
| Ephy reviewed outbox／v2 | proposal/receipt と設定済み Grant は既存の経路を継続。候補や Graph の参照から正本の変更、権限追加は発生しない。 |
| WebP KART／KMTD | KART の既存タグ、KMTD の JSON を継続。チャンクを書き換えればファイル全体の SHA-256 は変わる。再エンコードした派生物は原本と区別し、必要なメタデータを sidecar または将来の manifest で持ち運ぶ。WebP 全体の digest は外部に保持する。 |
| Board／PDF 引用 | カードの既存 `source` パスを別名として取り扱う。既存の引用のページ・矩形や新しい PDF digest（PR #349）を固定版のアンカーへ投影できる。 |
| `.karte` の PR #347 | 現行の単体 Markdown アーカイブを維持。G0 の ShareSnapshot は別の型で、既存 manifest の版や拡張子を変更しない。 |
| 決定ログ、訂正、Drive 同期 | 既存ストアと承認を正本として継続。G0 は専用の書込みや権限経路を増やさない。 |

## 権限と脅威

- 受信者の認可を、ルート、依存、派生物、投影された本文やメタデータに適用する。存在非開示の場合は名前・タグ・ID・ハッシュ・関係・件数を payload やエラーへ出さない。存在開示を別途許可した必須埋め込みだけ、出発元の投影 ID と共通の `restricted` 状態で表せる。
- Schema と整合性検証は投影の形状を制限する。Blob 本文や表示、ネットワーク、エラーが権限外のデータを漏らさないことは、実際の認可・投影アダプターの試験で確認する。Root への許可が得られない場合はスナップショットを返さない。
- GrantRef と埋め込みメタデータは入力データであり、受信側の権限は既存 Policy で再判定する。SHA-256 は整合性に使い、送信者の同定は認証済み transport に委ねる。
- 形式にローカルパスを含めない。将来の取込では ZIP の名前・symlink・重複・展開量・CRC／ハッシュと衝突を検証し、全検証後に原子的に配置する。共有済みの平文は回収を保証できない。

## 検証・移行・承認

- [Schema と合成 Fixtures](../../schemas/hybrid-sharing/v0.1/resource-graph.schema.json) は、不明版、循環、親版の取り違え、競合 Head、旧 doc_id、関係の欠損、座標、非開示対象の漏出を防ぐ形状を検証する。専用 CI は Windows、macOS Apple Silicon、Linux で Schema と Go を実行し、Schema のみの変更でも起動する。
- G0 の変更は OS や Wails に依存しない。既存のファイルの読み込み、保存、表示、同期に接続せず、差し戻しで復元できる。Windows の開発ツール未導入環境と Mac 実機の動作は **UNVERIFIED**。
- [HSH-02 の設計と合成 Fixture](../HSH-02_READ_ONLY_RESOURCE_RESOLVER.md) に、既存参照、名前変更、欠損、循環、複数 Head を定義した。次は読み取り専用解決器を合成データで検証する。その後 HSH-03 の投影を実装し、非開示対象を含む本文とメタデータに対して漏出テストを実施する。
- 実 Workspace への ID 台帳導入前に、既存パス別名との共存か段階的な書換えかを判断する。最初は共存を推奨する。移行が必要になった場合は、dry-run、重複一覧、回復手順を揃えて人間の承認を得る。main へのマージ、正式リリース、実データ移行、権限拡大、既存契約の非互換変更は承認が必要。
