# Karte Research Wall PoC

PDF・Markdown・画像・音声を，解釈や仮説と並べて検討するボードです．Karte本体の「コルクボード」タブと，独立したローカルPoCで同じ表示コードを使用します．独立サーバーはKarteのデータには書き込みません．

## Karte本体での利用

通常のフロントエンドビルドに`research-wall.html`が含まれます．ネイティブアプリの「コルクボード」タブから利用できます．

- 「管理資料から選ぶ」で既存のMarkdown・PDF・画像・音声を参照します．ドロップまたは「資料を追加」はKarteの既存の取り込み処理へ接続します．画像変換・メタデータ・音声の文字起こしも既存の設定を使用します．SVGはPNGへ描画して画像管理へ渡します．
- カードの「Karteで本文を編集」は通常のMarkdownエディタへ，画像は既存のメタデータ編集へ，音声は関連する文字起こしへ開きます．音声に関連する文書がなければ，音声パスを持つ空のメモを作ります．録音に含まれない発言は生成しません．
- PDFは既存のPDF表示へ開けます．「ボードへ戻る」で復帰できます．PDF本体の変更・OCRは実装していません．本文の編集・画像メタデータの保存後は，ボードへ戻ると最新の内容を読み直します．
- ボードは`content/research-<UUID>.board.md`へ自動保存します．既存ボードはファイル一覧または「ボードを開く」から開けます．原資料は`content/`，`data/image/`，`data/audio/`に保持し，ボードには管理相対パスを保存します．カードを外しても原資料は削除しません．
- 既存のボードID・タグ・ノート・独自カード情報を保持します．判断理由は`Edge.Description`，確認状態と引用の始点・終点は`Edge.Meta.researchWall`，ページ・時刻などは`Card.Meta.researchWall`に保存します．本文はYAMLの`body_markdown`として保存し，本文の見出しや区切りがボード構造に混入しないようにします．従来の本文形式も読み込めます．
- PDF上の引用はファイルの更新情報を保持します．原資料が変更された場合は古い矩形を確定位置として表示せず，引用を「要再確認」にします．Markdownの引用は本文の文字列と前後の文脈から再解決します．
- JSON読込は資料をKarteへ取り込み，新しいボードとして保存します．既存のボードは上書きしません．原資料のユーザーメタデータと音声メモを保持し，取り込んだMarkdownには新しい文書IDを割り当てます．JSON書出しはネイティブの保存ダイアログを使用し，資料本体を含む持ち運び可能なデータを作ります．
- ボードの自動保存で，編集中の原資料の未保存バッファを破棄しません．アプリ終了前に保留中のボード保存を完了し，保存できない場合は終了を止めます．
- 原資料のプレビューと「カードのメモ」を分けて保持します．従来の資料カードに書いた独自の分析も，原資料の再読込や配置変更で上書きしません．音声メモを含むJSONの復元時は，自動文字起こしを開始せず，保存済みメモを復元します．

`npm --prefix frontend run dev`のブラウザプレビューは仮想ワークスペースを使用します．このモードはブラウザのlocalStorageだけに保存し，実際のKarteデータは変更しません．

## 独立PoCの起動

Node.js 22.13以降を使用します．Karteの`frontend/node_modules`がある環境では，そのPDF.jsを利用できるため追加インストールは不要です．単独で使う場合は，このディレクトリで`npm install`を実行してください．

```sh
npm start
# http://127.0.0.1:4180/
```

`PORT=4181 npm start`でポートを変更できます．サーバーは127.0.0.1だけで待ち受けます．

## 試せる操作

- カードの移動，ボードのパン・ズーム，全体表示，全画面表示．狭い画面では左のライブラリを閉じられます．
- PDF・Markdown・画像・音声のファイル選択とドロップ．PDFはPDF.jsで表示し，ページを切り替えられます．
- 原資料のダブルクリック表示．PDFのページ・音声の時刻・Markdown本文などを参照する抜粋カードの作成．
- 本文の特定の語句をハイライトし，そこを始点／終点とする矢印を表示．上部の「テキスト」で本文をドラッグ選択し，「この箇所からつなぐ」を押して，参照先のカードをクリックします．
- PDFを開き，PDF上の文字を直接選択して参照を作成．図版や画像スキャンは「範囲を囲む」で矩形を指定できます．参照にはページと正規化した位置を保存し，「引用箇所を開く」で該当箇所を再表示します．
- PDFカードは幅いっぱいの拡大表示で，参照がある場合は引用箇所を中心に表示します．カード右上の「全体／拡大」でページ全体へ切り替えられます．タイトルと引用文字列はプレビューの外にも表示します．
- 「つなぐ」で始点・終点を順に選択し，支持・矛盾・関連・要確認と判断理由を保存．確認済み／未確認を実線／破線で区別．
- 関係一覧からの見直し，仮説メモの追加，資料の検索・種類フィルター，操作の取り消し．
- IndexedDBへの自動保存．ページ再読込後も原資料を含めて復元．JSONの書出し／読込みで別ブラウザへ持ち運び．

ショートカット：`V`選択，`H`移動，`T`テキスト，`C`つなぐ，`N`メモ，`F`全体表示，`Space`一時パン，`Esc`解除，`⌘/Ctrl+Z`取り消し．選択カードは矢印キーで移動，Shift併用で大きく移動できます．

## PoCの範囲

- サンプルはすべて架空です．画像はオリジナルのSVGスケッチ，PDFは架空の2ページ調査書です．サンプル音源は合成環境音で，表示された架空の発言は収録していません．波形も装飾です．
- 評価は利用者の判断を記録する仕組みです．OCRとAIによる関係推定は含みません．独立PoCは文字起こしやKarteの管理システムには接続しません．
- 1ファイル20MB，取り込む資料本体は合計80MB，Markdownは1MB，カード250枚まで．実際の保存容量はブラウザの空き容量にも依存します．
- Markdownは安全な簡易表示です．生HTML，外部画像，外部リンク，数式，表，埋込みは解釈しません．
- PDFは画像スキャンを表示できますがOCRは行いません．暗号化PDFは未対応です．音声の対応コーデックはブラウザに依存します．
- PDFのハイライト・図版の矩形はボード側の注釈です．PDF原本は変更しません．文字データを持たないスキャンは自動文字認識の代わりに範囲指定を使用します．
- 本文の引用は文字列・前後の文脈・位置を保存します．本文編集後は一意に特定できる場合に追従し，削除や曖昧さで特定できない場合は「要再確認」と表示します．
- ブラウザのサイトデータ削除で保存内容が消えます．JSONには取り込んだ資料の本体が含まれます．重要な作業はJSONでも保存してください．
- 独立PoCのJSON形式は`karte-research-wall/1`です．Karte側の「JSON読込」で管理ファイルと`.board.md`へ移行できます．

## 実装の分担

`app.mjs`・`model.mjs`・`style.css`は独立PoCと組み込み版で共有します．`model.mjs`のKarte形式との変換はNodeでも実行でき，Wails・DOM・ファイルシステムに依存しません．ファイル解決・保存・取り込みは`app_research_wall.go`，既存エディタとライフサイクルの接続は`frontend/src/components/research-wall.ts`，iframe側の通信は`frontend/src/research-wall/entry.ts`が担当します．通信は送信元iframeと同一オリジンを確認します．PDF.jsのワーカー・CMap・フォント・WASMはアプリに同梱します．

将来Karte_rendererへ表示モデルを移す場合にも，ネイティブの管理APIを必要としない境界を維持します．今回の機能にはCLIからのボード描画は含めていません．

## 検証

```sh
npm test
npm --prefix ../../frontend run typecheck
NODE_OPTIONS=--no-experimental-webstorage npm --prefix ../../frontend test -- --run
npm --prefix ../../frontend run e2e
# リポジトリルートで
# go test . ./internal/board
```

モデルの読込み検証，関係の重複防止，接続座標，表示範囲，MarkdownのHTML無効化，引用位置の復元，曖昧な引用の検出，PDF注釈の永続化を確認します．PDF・音声・ファイル選択・復元・テキスト選択からの接続はブラウザでも操作確認します．

Frontend E2Eでは，仮想管理ワークスペースを使ってカードの独自メモの保持，既存エディタとの往復，実際のPDFのページ・引用ハイライトの再読込を検証します．Goの管理API自体はGoテストで検証します．初回は`npm --prefix ../../frontend exec -- playwright install chromium`でテスト用ブラウザを取得してください．フロントまたは共有ボードコードの変更時にCIで実行し，失敗時の画面とトレースを保存します．
